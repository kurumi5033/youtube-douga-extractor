# 出演者検索からのYouTube動画抽出ツール

指定した出演者名（利用者がフォームで指定・最大3人・部分一致）でYouTubeを検索し、当月公開の動画のうち、タイトル・説明欄にその名前が含まれる動画だけを一覧表示・CSV出力するWebアプリです。

**フロント（`index.html`）は GitHub Pages でホスト**し、**YouTube Data APIキーと各種スプレッドシートIDは Google Apps Script（GAS）側にのみ保管**します。ブラウザのコードにもlocalStorageにもAPIキーは一切含まれません。個人への外販など、第三者に使わせる用途を想定した構成です。

## 構成

```
[利用者のブラウザ]                [Google Apps Script]              [YouTube Data API]
  index.html (GitHub Pages)  --->  Code.gs (Webアプリ)        --->  search.list / videos.list
  ・出演者名                        ・アクセスコードを台帳で検証
  ・アクセスコード                  ・APIキー/シートIDはスクリプトプロパティに保管
                              <---  ・検索結果をJSONで返却
                                    ・裏側で以下2枚のシートに記録（ベストエフォート）
                                          ↓
                        ┌───────────────────┴───────────────────┐
                 (購入者)管理台帳                      検索結果 / 利用ログ
              コード・有効期限・有効フラグを              検索のたびに1行ずつ追記
              読み取って可否を判定（検証専用）            （管理者向けの記録・監査用）
```

- **APIキーが漏れない理由**: ブラウザからGASへは「出演者名」と「アクセスコード」しか送りません。実際のYouTube APIキーはGAS内部（スクリプト プロパティ）にのみ存在し、フロント側のどこにも出てきません。
- **アクセスコードは台帳方式**: 単一の合言葉ではなく、(購入者)管理台帳スプレッドシートに購入者ごとのコードを行で登録します。有効期限切れ・無効化フラグでコードを個別に止められるため、購入者が増えても運用できます。
- **検索結果・利用ログは記録専用**: 画面表示・CSV出力の主役は引き続きGitHub Pages上の`index.html`です。2枚のシートはあくまで裏側の記録（監査・サポート対応用）で、書き込みに失敗しても検索結果の画面表示は止まりません。

## 出演者名の指定方法

出演者名は固定リストではなく、**利用者がフォームに入力する検索パラメータ**です（カンマ区切り・最大3人）。この名前を**そのままYouTube検索のクエリとしても使い**、かつ動画のタイトル・説明欄への部分一致でも判定します（検索キーワード欄は設けていません）。コードの編集や再デプロイは不要です。フロント側（`index.html`）とGAS側（`Code.gs`の`MAX_PERFORMERS_PER_REQUEST`）の両方で3人までの上限をチェックしています。

> **部分一致の実態について**: タイトル・説明欄との突き合わせ（`filterByPerformers`）自体は`indexOf()`による正真正銘の部分一致です。ただし出演者名はYouTube検索のクエリ（`q`パラメータ）としても使われ、そちらはYouTube自身の検索アルゴリズムに委ねられます。苗字だけなど短すぎる入力だと、YouTube側の検索結果（最大150件/人）に無関係な動画が多く混ざり、本来見つけたい動画が上位に出てこず結果に含まれないことがあります。「完全一致でないと機能しない」わけではなく「短い部分名だと検索結果に埋もれて見つからないことがある」というのが実態のため、フォーム上ではフルネームでの入力を推奨する注記をしています。

## 1. YouTube Data API v3 キーの取得手順

1. [Google Cloud Console](https://console.cloud.google.com/) にアクセスし、Googleアカウントでログインする。
2. 画面上部のプロジェクト選択メニューから「新しいプロジェクト」を作成する（例: `youtube-extractor`）。既存プロジェクトを流用してもよい。
3. 左メニューから「APIとサービス」→「ライブラリ」を開く。
4. 検索欄で「YouTube Data API v3」を検索し、該当APIを開いて「有効にする」をクリックする。
5. 左メニューの「APIとサービス」→「認証情報」を開き、「認証情報を作成」→「APIキー」を選択する。
6. 発行されたAPIキーをコピーする（後述の手順3でGASに設定します。ブラウザやフォームには入力しません）。
7. （推奨）作成したキーの「制限」で「APIの制限」を編集し、`YouTube Data API v3` のみを許可する。

> **無料枠について**: 1日あたり10,000ユニット。動画検索（`search.list`）は1回100ユニット消費します。上限に達した場合は翌日（太平洋時間基準）にリセットされます。

## 2. 3枚のスプレッドシートを準備する

Googleスプレッドシートで以下の3つを新規作成し、それぞれ1行目にヘッダーを入力してください（列の並び順・列数は固定です）。

**(購入者)管理台帳**（アクセスコードの検証専用）

| A | B | C | D |
|---|---|---|---|
| コード | 有効期限 | 有効フラグ | メモ |

- 有効期限は日付セル（空欄なら無期限扱い）。有効フラグは `TRUE` / `FALSE`。
- 購入者を追加・停止する時は、この台帳の行を追加・編集するだけで反映されます（コードの再デプロイ不要）。

**検索結果**（検索成功のたびにGASが自動追記）

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| 動画タイトル | 動画URL | サムネイルの画像 | 再生数 | 高評価数 | 出演者 | 検索日時 | 使用したアクセスコード |

- C列は`=IMAGE(...)`形式でGASが自動入力します。F列（出演者）は、指定した出演者名のうちどれに一致したかを追跡できるように残してあります。

**利用ログ**（検索の成否を問わず毎回1行追記）

| A | B | C | D | E |
|---|---|---|---|---|
| 日時 | アクセスコード | 出演者名 | 該当件数 | ステータス |

- アクセスコードの拒否（コード誤り・無効化・期限切れ）やサーバーエラーも「拒否: 理由」「エラー: 理由」の形でここに記録されます。クォータの使われ方や不正利用の兆候を確認する際に使ってください。

作成した3枚それぞれのスプレッドシートIDを、次の手順3で使います（URLの `.../d/【この部分】/edit` がIDです）。

> **共有設定の確認**: 3枚とも「リンクを知っている全員」に共有されていないか、必ず確認してください（初期状態は所有者のみのはずです）。台帳が第三者から編集可能だと、アクセスコードの検証自体が無意味になります。

## 3. Google Apps Script でバックエンド（窓口サーバー）を作る

1. [Google Apps Script](https://script.google.com/) にアクセスし、「新しいプロジェクト」を作成する。
2. デフォルトで表示されている `Code.gs` の中身を全て削除し、このリポジトリの [`google-apps-script/Code.gs`](google-apps-script/Code.gs) の内容を丸ごと貼り付ける。
3. 左メニューの歯車アイコン「プロジェクトの設定」を開き、「スクリプト プロパティ」に以下を追加する。

   | プロパティ名 | 値 |
   |---|---|
   | `YOUTUBE_API_KEY` | 手順1で取得したAPIキー |
   | `LEDGER_SHEET_ID` | (購入者)管理台帳のスプレッドシートID |
   | `RESULTS_SHEET_ID` | 検索結果のスプレッドシートID |
   | `USAGE_LOG_SHEET_ID` | 利用ログのスプレッドシートID |
   | `ARCHIVE_FOLDER_ID` | 月次アーカイブの保存先GoogleドライブフォルダID（下記4.参照） |

4. 右上の「デプロイ」→「新しいデプロイ」をクリックする。
5. 「種類の選択」の歯車アイコンから「ウェブアプリ」を選ぶ。
6. 以下のように設定する。
   - **実行するユーザー**: 自分
   - **アクセスできるユーザー**: 全員
7. 「デプロイ」をクリックし、Googleアカウントでのアクセス許可（スプレッドシートへのアクセスを含む）を求められたら承認する。
8. 発行された「ウェブアプリのURL」（`https://script.google.com/macros/s/xxxxx/exec` の形式）をコピーする。これが窓口サーバーのURLです。
9. Apps Scriptエディタ上部の関数選択プルダウンで `setupMonthlyArchiveTrigger` を選び、▷（実行）を1回だけクリックする。「毎月1日に検索結果シートを自動アーカイブする」トリガーが登録される（初回はDrive/Sheetsへのアクセス許可を追加で求められるので承認する）。

> **月次アーカイブの動作**: 毎月1日 0時台に、「検索結果」シートのその時点のデータを `ARCHIVE_FOLDER_ID` のフォルダ内に「検索結果_YYYYMM」（前月分）として作成・転記し、「検索結果」シートのデータ行を空にします（ヘッダーは残ります）。同名ファイルが既にある場合は新規作成せず、そこに追記します。今すぐ動作確認したい場合は、関数選択プルダウンで `archiveResultsSheet` を選んで手動実行することもできます。

> **Code.gs を後から修正した場合**: 保存しただけでは公開中のURLには反映されません。「デプロイ」→「デプロイを管理」→ 対象デプロイの鉛筆アイコン →「バージョン」で「新バージョン」を選んで再デプロイしてください。

## 4. フロントエンド（index.html）にURLを設定する

`index.html` 内の以下の行を、手順3-8で取得したURLに書き換えます。

```js
const GAS_ENDPOINT_URL = 'https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec';
```

## 5. GitHubリポジトリ作成 〜 GitHub Pages公開手順

### 5-1. リポジトリを作成する

1. [GitHub](https://github.com/) にログインし、右上の「+」→「New repository」をクリックする。
2. リポジトリ名を入力する（例: `youtube-douga-extractor`）。公開設定は「Public」を選択する（GitHub Pagesを無料枠で使う場合はPublic推奨）。
3. 「Create repository」をクリックする。

### 5-2. ローカルからリポジトリにpushする

このフォルダ（`E:\勉強部屋\youtube-douga-extractor`）で以下を実行してください。`<ユーザー名>` と `<リポジトリ名>` は自分のものに置き換えます。

```bash
git init
git add .
git commit -m "Add YouTube video extractor app"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

### 5-3. GitHub Pagesを有効化する

1. GitHub上のリポジトリページで「Settings」タブを開く。
2. 左メニューの「Pages」を選択する。
3. 「Build and deployment」の「Source」で「Deploy from a branch」を選択する。
4. 「Branch」で `main` ブランチ・フォルダは `/ (root)` を選択し、「Save」をクリックする。
5. 数十秒〜数分待つと、ページ上部に公開URL（例: `https://<ユーザー名>.github.io/<リポジトリ名>/`）が表示される。

### 5-4. 公開後の確認

1. 公開URLにアクセスし、画面が表示されることを確認する。
2. (購入者)管理台帳に自分用のテスト行（コード・有効フラグ`TRUE`）を追加し、そのコードと出演者名を入力して「検索開始」を押す。正常に検索・CSV出力できること、検索結果シート・利用ログシートにそれぞれ1行追記されることを確認する。
3. わざとアクセスコードを間違えて送信し、「アクセスコードが正しくありません。」と表示されること、利用ログに「拒否」として記録されることを確認する。
4. 台帳の有効フラグを`FALSE`にしたコードで送信し、正しく拒否されることを確認する。

### 更新時の反映方法

`index.html` を編集した場合は以下を実行すれば数十秒〜数分でGitHub Pagesにも反映されます。

```bash
git add .
git commit -m "Update app"
git push
```

`google-apps-script/Code.gs` を編集した場合は、GAS側で「3. の手順」の再デプロイ操作が別途必要です（GitHubへのpushだけでは反映されません）。

### うまく繋がらない場合（トラブルシューティング）

- ブラウザのコンソールにCORS関連のエラーが出る場合は、GASのデプロイ設定で「アクセスできるユーザー」が「全員」になっているか、URLが `/exec`（`/dev`ではない）で終わっているかを確認してください。
- 「管理者向けエラー: GAS_ENDPOINT_URL が未設定です」と表示される場合は、手順4の書き換えが漏れています。
- Code.gsを更新したのに反映されない場合は、上記の「再デプロイ」（新バージョンの発行）を忘れていないか確認してください。
- 検索結果・利用ログシートに記録が増えない場合は、スクリプト プロパティの`RESULTS_SHEET_ID` / `USAGE_LOG_SHEET_ID`が正しいか、GASの実行ログ（Apps Scriptエディタの「実行数」）でエラーが出ていないかを確認してください（記録の失敗は検索結果の画面表示自体には影響しません）。

## 6. 外販時の運用メモ

- **購入者の追加・停止**: (購入者)管理台帳に行を追加・編集するだけで反映されます。コードの変更や再デプロイは不要です。
- **コードの即時無効化**: 漏洩や退会者が出た場合は、台帳の該当行の有効フラグを`FALSE`にするだけで即座に無効化できます。
- **クォータの共有**: `YOUTUBE_API_KEY` は全利用者で共通です。利用者が増えると1日10,000ユニットの上限に達しやすくなるため、利用ログシートで利用状況を定期的に確認し、必要に応じて有料枠への引き上げ（Google Cloud Consoleでの申請）を検討してください。
- **同時アクセスについて**: Google Apps Scriptの無料利用枠には同時実行数の上限があります。想定利用者数が数十人規模を超える場合は、Cloudflare Workersなどよりスケールしやすい構成への移行を検討してください。

## セキュリティについて

- YouTube Data APIキー、および3枚のスプレッドシートのIDは、GAS内の「スクリプト プロパティ」にのみ存在し、`Code.gs`のソースコードにも、公開されるフロントエンドのコードにも書き込まれません。GitHubリポジトリを全て閲覧されても、これらは漏れません。
- ブラウザの開発者ツールで見えるのは「出演者名」と「アクセスコード」のみです。アクセスコードが漏れた場合の実害は「他人があなたの検索クォータを消費できてしまう」ことに限られ、YouTube APIキー自体が奪われるわけではありません。しかも台帳方式なので、漏れたコード1件だけを即座に無効化できます（他の購入者には影響しません）。
- (購入者)管理台帳・検索結果・利用ログの3枚は、必ず「所有者のみ（自分のGoogleアカウントのみ）」の共有設定を維持してください。特に管理台帳は購入者の識別情報を含むため、他のスプレッドシート以上に慎重に扱ってください。
- アクセスコードの検証は「フェイルクローズ」（台帳が読めない・設定が不完全な場合は許可ではなく拒否）で実装しています。検索結果・利用ログへの記録は逆に「ベストエフォート」（記録に失敗しても検索結果は返す）にしており、記録の不調が正規利用者をブロックしないようにしています。
- **スプレッドシートへの数式インジェクション対策**: 出演者名・アクセスコード（利用者からの入力）と、動画タイトル（YouTube側の外部データ）は、いずれも`=` `+` `-` `@`で始まる文字列だとGoogle Sheetsが数式として解釈してしまいます。これらをシートに書き込む前に、`sanitizeForSheet()`で先頭にアポストロフィを付与し、常に文字列として書き込まれるようにしています。
- **アクセスコードの総当たり対策**: 検証失敗が5分間に20回に達すると、以後5分間はすべてのリクエストを拒否します（`CacheService`による簡易実装）。GASの実行環境が切り替わるとカウントがリセットされる場合がある点は、この方式の限界として認識しておいてください。厳密なレート制限が必要な規模になった場合は、Cloudflare Workersなど専用のインフラへの移行を検討してください。
- **出演者名の数の上限**: 1回の検索で受け付ける出演者名は3人までです。フロント側（即座にエラー表示）とGAS側（`MAX_PERFORMERS_PER_REQUEST`）の両方でチェックしており、フロントを経由しない直接アクセスに対してもGAS側の上限が効きます。
